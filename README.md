# Telegram Digital Shop Bot — نسخه‌ی آپدیت (قیمت‌ها + حذف خودکار V2Ray + سود اخوان)

## 🆕 آپدیت جدید: بازگشت «عضویت اجباری» + سود اخوان برای همه‌ی ادمین‌ها + پنل ادمین کامل‌تر

### ۱) 🔐 عضویت اجباری (برگشت به پنل ادمین)
- دکمه‌ی **🔐 عضویت اجباری** دوباره در پنل مدیریت اضافه شد (`/admin`).
- دیگر نیازی به تنظیم دستی `CHANNEL_IDS` / `CHANNEL_LINKS` / `CHANNEL_LABELS` در Environment نیست؛ همه چیز از همان دکمه مدیریت می‌شود (مقادیر قبلی ENV هم به‌صورت خودکار در اولین اجرا به دیتابیس منتقل می‌شوند).
- مسیر: `پنل مدیریت ← 🔐 عضویت اجباری`
  - **➕ افزودن کانال**: یک پیام از کانال فوروارد کنید، یا یوزرنیم (`@channel`) یا آیدی عددی کانال (`-100...`) را بفرستید. ربات باید از قبل در آن کانال **ادمین** باشد.
  - **🗑 حذف** هر کانال از همان لیست.
  - **فعال/غیرفعال‌سازی** کل قابلیت عضویت اجباری با یک دکمه، بدون حذف لیست کانال‌ها.
- وقتی عضویت اجباری فعال و حداقل یک کانال ثبت شده باشد، کاربر عادی تا عضو نشدن در همه‌ی کانال‌ها نمی‌تواند از ربات استفاده کند (دقیقاً مثل نسخه‌های قبلی: پیام + دکمه‌های عضویت + «✅ بررسی عضویت»).
- ادمین‌های ربات از این محدودیت مستثنی هستند تا هیچ‌وقت از پنل خودشان قفل نشوند.

### ۲) 💐 سود اخوان برای همه‌ی ادمین‌ها
- دکمه‌ی **💐 سود اخوان** دیگر مخصوص یک ادمین خاص نیست و برای **تمام ادمین‌های ربات** در `ADMIN_IDS` (و ادمین‌های اضافه‌شده از پنل) نمایش داده می‌شود.
- تنظیم مبلغ اولیه، گزارش تراکنش‌ها، فایل CSV و اصلاح مبلغ، همگی مثل قبل کار می‌کنند؛ فقط حالا همه‌ی ادمین‌ها دسترسی دارند و پیام «سود جدید ثبت شد» هم برای همه‌ی ادمین‌ها ارسال می‌شود.

### ۳) 🧑‍💼 مدیریت ادمین‌ها (دکمه جدید)
- مسیر: `پنل مدیریت ← 🧑‍💼 مدیریت ادمین‌ها`
- هر ادمین می‌تواند با فرستادن آیدی عددی، ادمین جدید اضافه کند یا ادمین‌های اضافه‌شده از پنل را حذف کند.
- ادمین‌های پایه (همان‌هایی که در `ADMIN_IDS` محیط ست شده‌اند) از طریق پنل قابل حذف نیستند و فقط با تغییر Environment حذف می‌شوند.
- نیازی به ریستارت ربات نیست؛ تغییرات بلافاصله اعمال می‌شوند.

### ۴) 🛠 خاموش/روشن کردن ربات (حالت تعمیر و نگهداری — دکمه جدید)
- مسیر: `پنل مدیریت ← 🛠 خاموش کردن ربات`
- وقتی فعال باشد، کاربران عادی پیام «ربات موقتاً در حال به‌روزرسانی است» می‌بینند و ادمین‌ها همچنان دسترسی کامل دارند؛ مناسب زمان تغییر قیمت‌ها یا دیتابیس.

## 🆕 تغییرات این آپدیت

### آپدیت کارفرما — ۷ اکتبر ۲۰۲۶
- درخواست تست وایرساک پس از دریافت نام کاربری انگلیسی به‌صورت خودکار ساخته و تحویل می‌شود؛ ادمین‌ها از نتیجه مطلع می‌شوند و تأیید ادمین شرط تحویل نیست.
- هر کاربر به‌صورت پیش‌فرض یک تست دارد. ادمین‌ها از «🧪 مدیریت سهمیه تست» می‌توانند سهمیه هر کاربر را افزایش دهند یا عدد دقیق آن را تنظیم کنند؛ تست‌های تحویل‌شده در تاریخچه می‌مانند و تلاش ناموفق سهمیه را مصرف نمی‌کند.
- درخواست نام کاربری کوتاه است، کلمه «انگلیسی» بولد نمایش داده می‌شود، نام فارسی رد می‌شود و تا ورود نام معتبر، منوها و دکمه‌های ناوبری کاربر را از این مرحله خارج نمی‌کنند.
- V2Ray و محصولات هوش مصنوعی فقط مسیر تحویل دستی دارند؛ تحویل خودکار محصول فقط برای سرویس‌های گیمینگ WireGuard فعال است.
- دکمه «🛠 مدیریت EylanPanel» و داشبورد وضعیت/حساب‌های ثبت‌شده فقط در چت خصوصی ادمین نمایش داده می‌شود؛ در گروه‌ها این نام و داشبورد نمایش داده نمی‌شوند.

### ۱) 💲 تغییر قیمت سرویس‌ها (پنل ادمین)
- پنل مدیریت ← **💲 تغییر قیمت سرویس‌ها** ← انتخاب محصول ← ارسال قیمت جدید (به تومان، عدد).
- همه‌ی ادمین‌ها می‌توانند قیمت را عوض کنند. محصولی که قیمتش تغییر کرده در لیست علامت ✏️ دارد.
- دکمه‌ی «↩️ بازگشت به قیمت پیش‌فرض» قیمت را به مقدار `products.json` برمی‌گرداند.
- قیمت‌ها در جدول `price_overrides` دیتابیس ذخیره می‌شوند؛ با ریستارت یا آپدیت ربات از بین نمی‌روند و با «ارسال دیتابیس» هم جابه‌جا می‌شوند.
- قیمت جدید فقط روی خریدهای بعدی اثر دارد؛ سفارش‌های قبلی با قیمت زمان خرید می‌مانند.

### ۲) ✋ V2Ray فقط دستی
- تحویل خودکار V2Ray (از EylanPanel) **حذف شد**. بعد از تأیید فیش، سفارش V2Ray مستقیم وارد «تحویل دستی» می‌شود: ادمین لینک/فایل را می‌فرستد و ربات آن را داخل پیام آماده برای مشتری قرار می‌دهد.
- سفارش‌های وایرساک / وایرگارد امکان تحویل خودکار دارند؛ اکانت تست بدون تأیید ادمین خودکار تحویل می‌شود و هر کاربر یک سهمیه پایه دارد که از پنل قابل افزایش است.
- چون V2Ray از پنل دیگری تحویل می‌شود، دکمه‌ی «📊 وضعیت سرور» فقط برای وایرساک/تست نمایش داده می‌شود.

### ۳) 💐 سود اخوان
- (به‌روزرسانی: از آپدیت جدید، این بخش برای **همه‌ی ادمین‌ها** نمایش داده می‌شود، نه فقط اولین آیدی در `ADMIN_IDS`.)
- **🏁 تنظیم مبلغ اولیه**: عدد شروع (مثلاً `122000`) را ثبت می‌کنید. **از همان لحظه** سود هر فروش اضافه می‌شود؛ فروش‌های قبل از آن حساب نمی‌شوند.
- سود در لحظه‌ی **تکمیل/تحویل سفارش** ثبت می‌شود (هر سفارش فقط یک بار) و بلافاصله به اخوان پیام 🌹 «سود شما بعد از این خرید … شد» می‌رسد.
- نرخ‌ها (قابل ویرایش در `profit_rates.json`):

| محصول | سود اخوان |
|---|---|
| وایرساک ۵۰ گیگ | ۲۵,۰۰۰ تومان |
| وایرساک ۱۰۰ گیگ | ۵۰,۰۰۰ تومان |
| وایرساک ۲۰۰ گیگ | ۱۰۰,۰۰۰ تومان |
| V2Ray | هر گیگ ۷۵۰ تومان (مثلاً ۱۵ گیگ = ۱۱,۲۵۰) |

- **📋 گزارش تراکنش‌ها**: لیست صفحه‌بندی‌شده؛ هر ردیف: شماره سفارش، محصول، خریدار، تاریخ شمسی (وقت ایران)، سود افزوده‌شده و **سود بعد از آن خرید**.
- **📄 دریافت فایل گزارش کامل**: فایل CSV (باز شدن در Excel با فارسی درست) برای نشان دادن به کارفرما.
- **✏️ اصلاح مبلغ سود**: اگر عدد را دستی اصلاح کنید، خودِ اصلاح هم در گزارش ثبت می‌شود.

### 🔁 برگرداندن دیتابیس قبلی
1. ربات را با یکی از دو روش (پایتون/داکر) بالا بیاورید.
2. در تلگرام: `/admin` ← **📤 ارسال دیتابیس** ← فایل `.sqlite3` قبلی را به‌صورت *File* بفرستید ← **✅ تأیید**.
3. ربات قبل از جایگزینی یک بکاپ ایمنی برایتان می‌فرستد و جدول‌های جدید را خودش به دیتابیس قدیمی اضافه می‌کند؛ هیچ اطلاعات قبلی (کاربران، سفارش‌ها، سرویس‌ها، کیف پول) پاک نمی‌شود.
4. بعد از بازگردانی، اگر دیتابیس قبلی «سود اخوان» نداشته، یک‌بار **🏁 تنظیم مبلغ اولیه** را بزنید.

> نکته: ساده‌ترین راه برای انتقال، همین دکمه‌ی «📤 ارسال دیتابیس» است. اگر ترجیح می‌دهید، فایل قبلی را با نام `shop.sqlite3` داخل پوشه‌ی `data/` بگذارید و ربات را ریستارت کنید.

# Telegram Digital Shop Bot — Belmo / Python Ready

ربات فروش خدمات دیجیتال با Python + pyTelegramBotAPI و SQLite. این نسخه برای استقرار روی سرویس Python در Belmo آماده شده است و تحویل خودکار EylanPanel را فقط برای سرویس‌های **WireGuard گیمینگ** فعال می‌کند؛ V2Ray و محصولات هوش مصنوعی دستی تحویل می‌شوند.

## امکانات اصلی

- تأیید فیش توسط ادمین → «شروع تحویل»؛ برای WireGuard امکان انتخاب دستی یا خودکار وجود دارد و V2Ray/هوش مصنوعی مستقیم وارد تحویل دستی می‌شوند.
- تحویل دستی: ادمین اطلاعات/لینک را ارسال می‌کند و ربات آن را داخل پیام آماده برای مشتری قرار می‌دهد.
- تحویل خودکار محصول فقط برای WireGuard گیمینگ انجام می‌شود؛ V2Ray و محصولات هوش مصنوعی دستی هستند.
- دکمه «📊 وضعیت سرور» برای مشتری اضافه شده و وضعیت لحظه‌ای حجم باقی‌مانده، مصرف، زمان باقی‌مانده و آنلاین/آفلاین بودن سرویس را از API می‌گیرد.
- WireGuard: فقط `wg1` فعال می‌شود و OpenVPN ناخواسته فعال نمی‌شود.
- تنظیمات فنی Sing-box و وضعیت API برای رکوردهای قدیمی V2Ray حفظ شده‌اند؛ اما سفارش‌های جدید V2Ray فقط به‌صورت دستی تحویل می‌شوند.
- لینک Subscription هنگام تحویل خودکار WireGuard از API گرفته و در پیام کاربر قرار می‌گیرد.
- اگر username برای تحویل خودکار WireGuard قبلاً در پنل وجود داشته باشد، ربات پیش از تغییر، مالکیت آن را در دیتابیس محلی کنترل می‌کند.
- Retry تحویل خودکار WireGuard ایمن است: نتیجه API و `delivery_message_id` ذخیره می‌شود تا سفارش مجدد ساخته یا پیام دوباره ارسال نشود.
- دیتابیس قبلی با migration امن قابل استفاده است و ستون‌های API به‌صورت خودکار اضافه می‌شوند.
- اکانت تست WireGuard با `flexible_days`، `expiry_days=1` و `pending_activation_days=2` مدیریت می‌شود.

## Environment Variables

این‌ها متغیرهایی هستند که در Belmo → **Environment** باید تنظیم شوند. متغیرهای جدید مربوط به اتوماسیون EylanPanel با ⭐ مشخص شده‌اند.

```env
# Telegram / Store
BOT_TOKEN=توکن_ربات
ADMIN_IDS=123456789,987654321
# CHANNEL_IDS / CHANNEL_LINKS / CHANNEL_LABELS اختیاری شده‌اند؛ فقط برای Seed اولیه
# استفاده می‌شوند. بعد از اولین اجرا، کانال‌های عضویت اجباری را از پنل مدیریت
# (🔐 عضویت اجباری) اضافه/حذف کنید.
CHANNEL_IDS=-1001234567890,-1009876543210
CHANNEL_LINKS=https://t.me/example1,https://t.me/example2
CHANNEL_LABELS=کانال اول,کانال دوم
SUPPORT_USERNAME=@YourSupport
CARD_NUMBER=شماره کارت
CARD_OWNER=نام صاحب کارت
STORE_NAME=فروشگاه دیجیتال
CURRENCY_LABEL=تومان
CHANNEL_USERNAME=@YourChannel

# Runtime / DB
PORT=3000
DB_PATH=/app/data/shop.sqlite3

# EylanPanel
EYLAN_API_KEY=کلید_API_شما                    # ⭐ جدید/لازم برای اتوماسیون
EYLAN_API_DOMAIN=necro.gamegozardns2.shop:3500/r/necro   # ⭐
EYLAN_API_FALLBACK_DOMAIN=necro.gamegozardns2.shop:3500 # ⭐
EYLAN_API_TIMEOUT=20                            # ⭐
EYLAN_ALLOW_HTTP=false                          # ⭐ جدید؛ فقط اگر پنل واقعاً HTTP است true کنید
EYLAN_TRIAL_DATA_LIMIT=                         # ⭐ اختیاری؛ خالی=نامحدود، مثلاً 10=ده گیگ
EYLAN_SINGBOX_INBOUNDS=                         # ⭐ جدید/اختیاری؛ مثلاً reality-main,ss-main
EYLAN_REQUIRED_NODE_NAMES=Germany-4,Germany-2,Turkey-1-A,Turkey-3  # ⭐ جدید؛ چهار Node اجباری برای کاربران خودکار
```

### متغیرهای جدید این آپدیت

این ۸ متغیر مربوط به اتصال خودکار ربات به EylanPanel هستند؛ مواردی که «لازم» یا «اختیاری» مشخص شده‌اند را مطابق جدول زیر در **Belmo → Environment** تنظیم کنید:

| متغیر | وضعیت | کاربرد |
|---|---|---|
| `EYLAN_API_KEY` | لازم | کلید API پنل در Header `X-API-KEY` |
| `EYLAN_API_DOMAIN` | لازم | دامنه/مسیر اصلی API؛ در این پروژه مقدار پیشنهادی `necro.gamegozardns2.shop:3500/r/necro` است |
| `EYLAN_API_FALLBACK_DOMAIN` | لازم | آدرس جایگزین؛ در این پروژه `necro.gamegozardns2.shop:3500` |
| `EYLAN_API_TIMEOUT` | اختیاری | timeout هر درخواست API؛ پیش‌فرض ۲۰ ثانیه |
| `EYLAN_ALLOW_HTTP` | اختیاری | فقط برای حالتی که API عمداً با HTTP ساده در دسترس باشد؛ پیش‌فرض `false` |
| `EYLAN_TRIAL_DATA_LIMIT` | اختیاری | حجم اکانت تست WireGuard بر حسب GB؛ خالی/`0` یعنی بدون محدودیت حجم |
| `EYLAN_SINGBOX_INBOUNDS` | اختیاری | tagهای inbound برای V2Ray/Sing-box، جداشده با کاما؛ خالی باشد از API کشف می‌شوند |
| `EYLAN_REQUIRED_NODE_NAMES` | اختیاری با مقدار پیش‌فرض چهار Node پروژه | نام نمایشی Nodeها، جداشده با کاما؛ ربات نام‌ها را از `GET /api/v1/nodes` به ID تبدیل می‌کند و هر چهار Node را در Create/Update می‌فرستد |

**رمز ورود خود پنل EylanPanel (`username/password`) جزو متغیرهای این پروژه نیست.** چیزی که API لازم دارد `EYLAN_API_KEY` است.

### معنی متغیرهای EylanPanel

`EYLAN_API_KEY` کلید خصوصی API است و فقط باید در Environment نگهداری شود. طبق مستندات فعلی EylanPanel، احراز هویت API با Header به نام `X-API-KEY` انجام می‌شود.

`EYLAN_API_DOMAIN` و `EYLAN_API_FALLBACK_DOMAIN` دو Base URL هستند تا پروژه بتواند هر دو حالت دامنه‌ای که برای پنل داری را امتحان کند. ربات آدرس API را خودش از روی این دو مقدار می‌سازد.

`EYLAN_API_TIMEOUT` زمان انتظار هر درخواست API بر حسب ثانیه است.

`EYLAN_ALLOW_HTTP` به‌صورت پیش‌فرض `false` است تا کلید API روی HTTP ساده ارسال نشود. فقط وقتی آن را `true` کنید که endpoint پنل شما عمداً فقط با HTTP در دسترس است.

`EYLAN_TRIAL_DATA_LIMIT` سهمیه حجم اکانت تست است؛ خالی بودن یا `0` یعنی بدون محدودیت حجم.

`EYLAN_SINGBOX_INBOUNDS` برای محصولات V2Ray/Sing-box اختیاری است. اگر خالی باشد، ربات از endpoint `GET /api/v1/public/singbox/my_inbounds`، inboundهای مجاز همان API Key را می‌خواند و از tag آن‌ها استفاده می‌کند. EylanPanel این endpoint را برای inboundهای مجاز کلید API مستند کرده است.

`EYLAN_REQUIRED_NODE_NAMES` چهار Node اجباری فروشگاه را مشخص می‌کند: `Germany-4`، `Germany-2`، `Turkey-1-A` و `Turkey-3`. در تحویل خودکار WireGuard، ربات ابتدا `GET /api/v1/nodes` را می‌زند، نام‌ها را پیدا می‌کند و ID هر چهار مورد را داخل Create/Update می‌فرستد. اگر حتی یکی از این چهار Node برای API Key قابل مشاهده نباشد، تحویل اتوماتیک عمداً متوقف می‌شود تا کاربر با سرویس ناقص تحویل نشود.

> **رمز ورود پنل EylanPanel در ربات لازم نیست.** API با API Key کار می‌کند؛ بنابراین username/password ورود دستی پنل را داخل Environment یا JSON قرار ندهید.

## Belmo — تنظیمات Deploy

این پروژه عمداً برای **Python** آماده شده است. در ریشه پروژه فایل `.python-version` با مقدار `3.11` و `Procfile` با دستور زیر قرار دارد:

```text
web: python -u bot.py
```

در این نسخه `Dockerfile`، `deplexo.yaml` و `railway.json` حذف شده‌اند تا Belmo آن را به‌صورت پروژه Python تشخیص دهد، نه Docker. Belmo برای پروژه‌های Python از `requirements.txt` / `.python-version` استفاده می‌کند و برای سرویس API نیز پورت `PORT` را در اختیار برنامه می‌گذارد.

ربات هم یک HTTP health endpoint سبک روی `0.0.0.0:$PORT` بالا می‌آورد تا health check پلتفرم پاسخ بگیرد، در حالی که خود ربات با Telegram long polling کار می‌کند.

### نکته بسیار مهم درباره SQLite در Belmo

فایل‌سیستم سرویس‌های اجراشونده روی Belmo برای state دائمی نباید بدون بررسی فرض شود؛ مستندات Belmo برای workloadهای طولانی‌مدت استفاده از دیتابیس مدیریت‌شده را برای state ماندگار توصیه می‌کنند و Postgres به‌صورت سرویس مستقل ارائه می‌شود.

این پروژه هنوز SQLite است؛ بنابراین **قبل از production باید مطمئن شوید مسیر `DB_PATH` واقعاً persistent است یا دیتابیس را به Postgres مهاجرت دهید.** اگر Belmo برای سرویس فعلی شما persistent storage در اختیار نمی‌گذارد، Restore کردن فایل SQLite بعد از هر redeploy کافی نیست و داده‌ها ممکن است از بین بروند.

## چک‌لیست Deploy روی Belmo

1. Repository را روی branch `main` به‌صورت **Python** Deploy کنید. وجود `requirements.txt` و `.python-version` باعث می‌شود Python تشخیص داده شود؛ اگر در داشبورد Start Command قابل تنظیم است، مقدار زیر را قرار دهید:

```text
python -u bot.py
```

2. همه Environment Variableهای بخش بالا را در **Belmo → Environment** قرار دهید. `EYLAN_API_KEY` را Secret نگه دارید.

3. `EYLAN_API_DOMAIN` را ابتدا روی آدرس `/r/necro` و `EYLAN_API_FALLBACK_DOMAIN` را روی آدرس مستقیم تنظیم کنید؛ کد هر دو Base URL را بررسی می‌کند. اگر API فقط با HTTP ساده قابل دسترسی است، فقط در همان صورت `EYLAN_ALLOW_HTTP=true` بگذارید.

4. دیتابیس قبلی را روی **همان مسیر persistent** قرار دهید و بعد از استارت اجازه دهید `init_db()` migrationهای لازم را خودش اجرا کند؛ نیازی به حذف یا بازسازی دیتابیس قبلی نیست.

5. قبل از تحویل واقعی، یک خرید آزمایشی WireGuard و یک خرید آزمایشی V2Ray انجام دهید. برای V2Ray اگر `EYLAN_SINGBOX_INBOUNDS` خالی است، API باید حداقل یک inbound مجاز برگرداند.

6. اگر Deploy قبلی روی Belmo وضعیت `Failed` داشته، بعد از جایگزینی این نسخه یک Deploy تازه بزنید و **Logs** را بررسی کنید. این نسخه دیگر Dockerfile ندارد و برای Python آماده شده است.

## نکته مهم درباره دکمه Back موبایل

ربات تلگرام به رویداد «دکمه Back فیزیکی/سیستمی موبایل» دسترسی ندارد. بنابراین هیچ کد Telegram Bot API نمی‌تواند تشخیص دهد کاربر در اندروید دقیقاً دکمه Back گوشی را زده است یا بر اساس آن دو رفتار متفاوت اجرا کند.

برای همین در این نسخه:

- منوی اصلی و منوهای داخلی با **Reply Keyboard** در پایین صفحه کنترل می‌شوند.
- در مراحل داخلی دکمه `⬅️ بازگشت` و `🏠 منوی اصلی` در پایین صفحه وجود دارد.
- دکمه `✖️ بستن کیبورد` برای مخفی‌کردن Reply Keyboard اضافه شده است.
- از خود Telegram، Back/Close چت همچنان توسط کلاینت Telegram مدیریت می‌شود.

این تنها رفتار قابل اتکا از سمت Bot API است و ادعای دریافت مستقیم Back گوشی توسط ربات صحیح نیست.


### تغییرات این آپدیت — وضعیت سرور و تحویل دوحالته
- گزینه `📊 وضعیت سرور` به منوی اصلی مشتری و جزئیات سرویس اضافه شده است. برای سرویس‌های WireGuard/Trial، ربات اطلاعات مصرف و باقی‌مانده را از API می‌گیرد و زمان باقی‌مانده را بر اساس تاریخ انقضا محاسبه می‌کند؛ برای سرویس بدون تاریخ انقضا «نامحدود» نمایش داده می‌شود.
- اگر پاسخ جزئی API قدیمی باشد، `GET /api/v1/users/list_all` برای تکمیل اطلاعات حجم/انقضا استفاده می‌شود و در صورت قطعی موقت API، کارت محلی سرویس به‌عنوان fallback فقط برای نمایش استفاده می‌شود.
- در تحویل سفارش WireGuard، ادمین بین `⚡ تحویل اتوماتیک` و `✋ تحویل دستی` انتخاب می‌کند؛ V2Ray و هوش مصنوعی مستقیم وارد تحویل دستی می‌شوند.
- تحویل اتوماتیک محصول فقط برای سرویس‌های گیمینگ WireGuard فعال است. اکانت تست WireGuard نیز بدون تأیید ادمین خودکار تحویل می‌شود.
- در خطای تحویل اتوماتیک، گزینه Retry و گزینه تبدیل همان سفارش به تحویل دستی باقی می‌مانند؛ سفارش دوباره ساخته نمی‌شود.
- وضعیت `delivery_mode` برای سفارش در دیتابیس ذخیره می‌شود تا حالت دستی و اتوماتیک هنگام Retry یا دریافت پیام ادمین با هم قاطی نشوند.
- چهار Node تصویر پروژه، یعنی `Germany-4`، `Germany-2`، `Turkey-1-A` و `Turkey-3`، برای هر Create/Update خودکار اجباری هستند. ربات ID هر Node را با `GET /api/v1/nodes` پیدا می‌کند و اگر حتی یکی از چهار Node قابل مشاهده نباشد، provisioning را عمداً متوقف می‌کند.

### تغییرات آخرین نسخه
- دکمه «✖️ بستن کیبورد» حذف شده است؛ بسته‌شدن Reply Keyboard به رفتار عادی Back خود تلگرام واگذار شده است.
- پیام‌های تکراری درباره «استفاده از دکمه‌های پایین» حذف شده‌اند تا روند خرید خلوت و حرفه‌ای بماند.
- بعد از تأیید پرداخت، سفارش WireGuard امکان انتخاب «⚡ تحویل اتوماتیک» یا «✋ تحویل دستی» دارد؛ سفارش‌های V2Ray و هوش مصنوعی مستقیماً در مسیر تحویل دستی قرار می‌گیرند.
- در خطای تحویل اتوماتیک، علاوه بر Retry، گزینه «✋ تبدیل به تحویل دستی» هم وجود دارد تا ادمین بدون تغییر وضعیت سفارش بتواند لینک/فایل را خودش تحویل دهد.
- دکمه «📊 وضعیت سرور» به منوی اصلی و جزئیات سرویس اضافه شده است و برای هر سرویس WireGuard/Trial وضعیت زنده API را نمایش می‌دهد. اگر API موقتاً در دسترس نباشد، کارت محلی سرویس به‌عنوان fallback نمایش داده می‌شود و سفارش/سرویس دست‌کاری نمی‌شود.
- برای تحویل خودکار WireGuard، هر چهار Node `Germany-4`، `Germany-2`، `Turkey-1-A` و `Turkey-3` اجباری‌اند. ربات ID واقعی Nodeها را از API پیدا می‌کند و در Create/Update می‌فرستد؛ اگر یکی پیدا نشود، تحویل متوقف می‌شود و سرویس ناقص ساخته/تمدید نمی‌شود.
- پس از تحویل، Reply Keyboard اصلی همراه پیام نهایی برای مشتری نمایش داده می‌شود.
- گزینه «نحوه اتصال» برای کاربری که خرید تکمیل‌شده دارد، آموزش آخرین سرویس خریداری‌شده را مستقیماً باز می‌کند؛ در غیر این صورت انتخاب سرویس نمایش داده می‌شود.
- کارت بانکی از طریق `CARD_NUMBER` و `CARD_OWNER` در Belmo → Environment تنظیم می‌شود و بهتر است اطلاعات پرداخت واقعی را در GitHub Commit نکنید.

### ۴. مدیریت موجودی در پنل ادمین
مسیر: `پنل مدیریت → 👛 مدیریت موجودی → ارسال آی‌دی عددی کاربر`

کارت کاربر شامل نام، یوزرنیم، وضعیت، موجودی فعلی و مبلغ رزروشده روی سفارش‌های باز. عملیات:

| دکمه | کار |
|---|---|
| ➕ افزایش موجودی | مبلغ را به موجودی اضافه می‌کند |
| ➖ کاهش موجودی | مبلغ را کم می‌کند (کمتر از صفر نمی‌رود) |
| 🔢 تنظیم مقدار دقیق | موجودی را روی عدد دلخواه ست می‌کند |

- هر تغییر در جدول `transactions` ثبت می‌شود و به کاربر پیام اطلاع‌رسانی می‌رود.

### ۵. خرید با کیف پول
- **پیش‌فاکتور و صفحه پرداخت** به کاربر می‌گویند: «با توجه به موجودی کیف پول شما، به‌جای X تومان فقط Y تومان واریز کنید.»
- **پیام فیش به ادمین** شامل: قیمت سرویس، موجودی کیف پول کاربر که کسر شد، مبلغ فیش، موجودی فعلی، و یک خط توضیح صریح که چرا مبلغ فیش کمتر از قیمت سرویس است.
- **اگر موجودی کیف پول برای خرید کافی باشد**، سفارش **بدون نیاز به فیش** نهایی می‌شود (`finalize_wallet_only_order`). برای وایرساک/V2Ray ابتدا نام کاربری پرسیده می‌شود، سپس سفارش به صف تحویل ادمین می‌رود با برچسب «💳 نحوه پرداخت: کیف پول (بدون فیش)» و ذکر مبلغ کسرشده.
- بعد از خرید، موجودی استفاده‌شده از کیف پول کسر شده باقی می‌ماند (رزرو همان لحظه ثبت سفارش انجام می‌شود).

### ۶. باگ‌های جانبی رفع‌شده
- `KeyError` در `cb_pay` و کرش `invoice_text` وقتی محصولی از `products.json` حذف شده باشد.
- در حالت پرداخت کامل با کیف پول، قبلاً فقط یک toast نمایش داده می‌شد و **هیچ پیامی به کاربر ارسال نمی‌شد**.
- در همان حالت، **نام کاربری سرویس اصلاً گرفته نمی‌شد** و ادمین نمی‌توانست پنل بسازد.
- زدن «بازگشت» در مرحله نام کاربری، سفارش را بلاتکلیف و موجودی را قفل رها می‌کرد؛ حالا سفارش لغو و موجودی آزاد می‌شود.
- حلقه شدن دکمه «بازگشت» در صفحه «💰 موجودی».
- `SERVICE_LABELS[service]` روی سرویس ناشناخته کرش می‌کرد.

### ۷. تغییر دیتابیس
ستون `service_username` به جدول `active_services` اضافه شد، همراه با مایگریشن امن `ALTER TABLE` برای دیتابیس‌های موجود. نیازی به پاک کردن دیتابیس نیست.
## اتوماسیون EylanPanel

### WireGuard

پلن‌های `wireguard-50gb-1m`، `wireguard-100gb-1m` و `wireguard-200gb-1m` در `eylan_plans.json` تعریف شده‌اند:

- حجم: به‌ترتیب ۵۰ / ۱۰۰ / ۲۰۰ گیگ
- اعتبار: ۳۰ روز
- `enable_wg1=true`
- `enable_openvpn=false`

اکانت تست `wireguard-trial` نیز با `flexible_days`، یک روز اعتبار از اولین activation و حداکثر دو روز pending تعریف شده است.

### V2Ray / Sing-box (تحویل دستی)

محصولات V2Ray از EylanPanel به‌صورت خودکار تحویل داده نمی‌شوند و سفارش آن‌ها فقط مسیر دستی دارد. تنظیمات `v2ray-*` در `eylan_plans.json` و کد API برای سازگاری با سرویس‌ها/رکوردهای قدیمی و قابلیت وضعیت سرور باقی مانده‌اند؛ این تنظیمات به معنی فعال بودن تحویل خودکار V2Ray نیستند. حجم هر محصول از خود Product خوانده شده و payload انقضای ثابت برای V2Ray ارسال نمی‌شود، چون پلن فروش فعلی «زمان نامحدود» تعریف شده است.

```text
enable_singbox = true
enable_wg1 = false  (فقط برای User جدید)
enable_openvpn = false (فقط برای User جدید)
singbox_inbounds = [ ... ]
```

در helper فنی سازگار با رکوردهای قدیمی، تنظیم V2Ray هنگام PUT پروتکل‌های دیگر را بدون دلیل خاموش نمی‌کند؛ این مسیر برای تحویل سفارش‌های جاری V2Ray استفاده نمی‌شود.

### Endpointهای استفاده‌شده

ربات از Endpointهای رسمی زیر استفاده می‌کند:

```text
GET  /api/v1/status
POST /api/v1/users
GET  /api/v1/users/<username>
GET  /api/v1/users/list_all
GET  /api/v1/nodes
PUT  /api/v1/users/<username>
GET  /api/v1/users/<username>/sub
GET  /api/v1/users/<username>/all_ovpn_links
GET  /api/v1/users/<username>/wg1_files
GET  /api/v1/public/singbox/my_inbounds
```

این مسیرها در مستندات فعلی EylanPanel وجود دارند و API برای همه آن‌ها به `X-API-KEY` نیاز دارد.

### جلوگیری از User تکراری

برای `POST /api/v1/users` بعد از خطای transport، کلاینت کورکورانه درخواست را دوباره ارسال نمی‌کند؛ ابتدا با `GET /users/<username>` بررسی می‌کند که POST احتمالاً در پنل ثبت شده یا خیر. این کار برای جلوگیری از Duplicate Account هنگام timeout طراحی شده است.

همچنین اگر username در EylanPanel وجود داشته باشد ولی در دیتابیس محلی متعلق به کاربر فعلی ثبت نشده باشد، تحویل متوقف می‌شود و ربات اکانت شخص دیگری را تغییر نمی‌دهد.

### Retry تحویل تلگرام

ستون `delivery_message_id` به جدول `orders` اضافه شده است. اگر ساخت سرویس موفق شود ولی اجرای دوباره لازم شود، ربات می‌تواند از لینک و پیام قبلی استفاده کند و از ارسال دوباره محصول جلوگیری کند.

## دیتابیس قبلی

دیتابیس قبلی را می‌توانید بعد از Deploy نسخه جدید Restore کنید. `init_db()` قبل/بعد از Restore migration امن را اجرا می‌کند و ستون‌های زیر را در صورت نبودن اضافه می‌کند:

```text
orders.service_username
orders.api_username
orders.api_link
orders.api_status
orders.api_error
orders.delivery_message_id
orders.delivery_mode
active_services.service_username
```

پاک کردن دیتابیس قبلی لازم نیست.

## تست قبل از استقرار

```bash
python -m py_compile bot.py eylanpanel_api.py
```

سپس در Belmo یک Deploy آزمایشی انجام دهید و در Logs این موارد را بررسی کنید:

```text
Connected to Telegram as ...
Health server listening on 0.0.0.0:<PORT>
Bot started ...
```

قبل از اولین فروش واقعی، یک username آزمایشی روی پنل بسازید و این سناریوها را تست کنید:

```text
1) WireGuard → تحویل اتوماتیک → باید هر چهار Node روی User فعال باشند و لینک برای کاربر ارسال شود.
2) V2Ray و اکانت هوش مصنوعی → فقط تحویل دستی؛ لینک/اطلاعات ادمین در پیام آماده قرار بگیرد.
3) خطای API در WireGuard → Retry و «تبدیل به تحویل دستی» هر دو کار کنند.
4) اکانت تست WireGuard → پس از نام کاربری انگلیسی معتبر، خودکار تحویل شود؛ نام نامعتبر سهمیه را مصرف نکند.
5) سهمیه پیش‌فرض کاربر یک تست باشد و ادمین بتواند از پنل آن را افزایش دهد.
6) برای سرویس پشتیبانی‌شده، دکمه «📊 وضعیت سرور» اطلاعات باقیمانده را نشان دهد.
```
